# Shiplog 0.2.0 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers-ruby:subagent-driven-development (recommended) or superpowers-ruby:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Implement `docs/superpowers/specs/2026-10-26-shiplog-0.2.0-design.md`. That covers a configurable product-updates switcher, a better default roadmap, one changelog entry per gem upgrade, and tighter roadmap copy.

**Architecture:**
- **Switcher and roadmap defaults:** move from Trackberry's view overrides into the gem as partials, class keys and config, with plain-CSS defaults in `@layer shiplog`.
- **Upgrade detection:** a new `Shiplog::Sync::UpgradeDetector`, run for merged PRs that touch `Gemfile.lock`. It reads the lockfile at base and merge, diffs tracked gems with `Bundler::LockfileParser`, and lists the gem repo's PRs between the two refs. It stores the result in `shiplog_pull_request_upgrades`. `ChangeCandidates` and `Rewriter::Prompt` use it.

**Tech Stack:** Ruby 4.0.9, Rails 8.1.4, PostgreSQL, Minitest, WebMock, Capybara and Selenium (system tests). Bundler's `LockfileParser` is stdlib-adjacent and already loaded by Bundler, so it adds no new runtime dependency.

**Conventions:** as in the 0.1 plan.
- TDD: each failing test is seen to fail first.
- `rtk proxy bin/rails test`, `bin/rails test test/system` and `bin/rubocop` pass at each commit.
- Conventional commits.
- GraphQL documents are checked by `test/shiplog/github/queries_test.rb`, and live ones by `test/live` (`SHIPLOG_LIVE_GITHUB=1`).

Verified on 2026-10-26 against real data: trackberry#1952 touched `Gemfile.lock`. Its base and merge lockfiles parse to market_data 0.2.1 → 0.2.2. `compare/0.2.1...0.2.2` on Trackberry/market_data gives 6 commits, whose associated PRs are #38 and #39.

### Task 4: Upgrade detection

**Files:**
- migration `db/migrate/20261027000001_create_shiplog_pull_request_upgrades.rb`, with:
  - columns `pull_request_id` (FK), `gem_name`, `from_ref`, `to_ref`, `gem_repository`, `changes` (jsonb, default []) and timestamps;
  - a unique index on [pull_request_id, gem_name];
- `app/models/shiplog/pull_request_upgrade.rb`;
- `app/models/shiplog/sync/upgrade_detector.rb`;
- queries: `PULL_REQUESTS`/`PULL_REQUEST` gain `baseRefOid mergeCommit { oid } files(first: 100) { nodes { path } }`, plus a new `BLOB_TEXT` query (`object(expression:) { ... on Blob { text } }`) and `COMMIT_PULL_REQUESTS`;
- `lib/shiplog/github/client.rb` gains a small REST `get(path)` for `compare`;
- fixtures and tests.

- [ ] Write the failing tests, with WebMock fixtures modelled on the verified trackberry#1952 data:
  - a merged PR without `Gemfile.lock` in its files isn't inspected (no blob requests);
  - with it, the lockfiles diff to market_data 0.2.1 → 0.2.2, refs resolve (`v0.2.2`, then `0.2.2`), the compare lists commits, and their associated PRs are stored as `changes` (number, title, a 300-character body excerpt, url), capped at 50 and de-duplicated;
  - a git-sourced gem uses revisions;
  - an untracked gem (e.g. the public `holidays`) is ignored;
  - an unresolvable tag or an inaccessible repo stores the upgrade with empty `changes` and logs a warning;
  - detection is idempotent (it upserts on [pull_request_id, gem_name]);
  - the GraphQL fragment test still passes, and the live test covers `BLOB_TEXT` on Trackberry/shiplog.
- [ ] Wire it into `RepositorySync` and `RefreshJob`, after a merged PR is imported, for repos with `changelog: true`, bounded per sync.
- [ ] Commit `feat: detect gem upgrades in merged pull requests`.
