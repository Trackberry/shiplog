# Shiplog 0.3.0 — Design

Builds on 0.2.0. Decisions are the user's, made on 2026-10-26. Everything ships together as 0.3.0.

## 1. Entry permalinks

- Every approved feature and change entry gets a page at `/changelog/:slug`.
  - The slug is made from the title when the entry is first approved, parameterized and made unique with a `-2` suffix.
  - It is stored in a new `slug` column (unique index, partial on non-null).
  - Later title edits keep the slug, so links never break.
  - Roadmap entries get no permalink.
- The page shows:
  - the entry (category, date, title, body, images, area);
  - "← Back to the changelog", linking to the month anchor;
  - previous and next entries.
- `content_for :title` and `content_for :shiplog_description` (the body, truncated) are set. So is an Open Graph block (`content_for :shiplog_og`), which the engine layout renders and host layouts can render; this is documented, like `:shiplog_robots`.
- A draft, discarded or unknown slug returns 404.
- The changelog list links each title to its permalink.
- The ETag covers the entry, plus its neighbours' ids and `updated_at`.
- New class keys: `permalink` (the article wrapper), `permalink_back`, `permalink_nav` and `permalink_nav_link`.

## 2. Atom feed

- `/changelog.atom` serves the latest 50 approved feature and change entries.
  - The entry id is a tag URI built from the permalink.
  - Fields: title, updated (`approved_at`/`updated_at`), published (`released_on`), content (HTML rendered from the body with `simple_format`, plus images as absolute URLs) and category (area).
- Discovery: a `<link rel="alternate" type="application/atom+xml">` in the engine layout through `content_for :shiplog_feed`, which host layouts can render too. There is also a visible "Subscribe (Atom)" link on the changelog page.
- Caching: ETag / `fresh_when` as for the pages.
- Search, areas and locale: the feed follows `?area=` when given, and the request locale for translations.

## 3. "What's new": unseen count

- Shiplog doesn't know about users, so the host supplies the "last seen" timestamp:
  - `Shiplog.unseen_count(since:)` returns the number of approved feature and change entries with `approved_at > since`, or all of them when `since` is nil, capped at 99.
  - `Shiplog::UnseenHelper#shiplog_unseen_count(since)` exposes the same count as a view helper, which hosts include with `helper Shiplog::UnseenHelper`.
  - `config.on_changelog_seen = ->(controller) { … }` is called on each changelog index or permalink view, before it renders (a 304 included), so a host can stamp `current_user.update_column(:changelog_seen_at, Time.current)`. It defaults to nil.
- The count is a single indexed COUNT query, using the `(status, released_on)` index or a new `(status, approved_at)` index.
- Trackberry renders a dot or count next to a Changelog link in the app navbar. That part is host work, in the Trackberry follow-up.

## 4. Product areas, detected by AI

- A new table `shiplog_areas` (`name`, `slug` unique, `position`) and `entries.area_id` (nullable FK).
- **Detection:** the rewriter's JSON reply gains `"area"`, the name of one existing area, or a new short name of 1–3 words when none fits.
  - The prompt lists the existing areas and asks the AI to reuse one where possible.
  - A new name creates the area: matched case-insensitively against existing names, and capped at `config.max_areas` (default 8). Past the cap, the AI must choose an existing one. A name that resolves to nothing (cap reached, invalid) keeps the entry's current area; only an explicit valid name changes it.
- **Backfill:** an admin "Detect areas" action on a new Areas page enqueues a job. It asks the AI once, with up to 200 approved entry titles, to propose up to `max_areas` areas, then assigns each entry with batched classification prompts that send titles only.
- **Admin:**
  - An Areas page to rename, reorder and merge areas. Merging moves the entries and deletes the source area.
  - A per-entry area select on the edit page, including "None".
  - The area appears as a badge in the inbox.
- **Public:**
  - The changelog shows an area filter, as links (`?area=slug`), above the list when at least 2 areas have approved entries.
  - It combines with `q` and pagination, and is part of the ETag.
  - Each entry shows its area as a tag.
  - Roadmap cards are unchanged.
- New class keys: `areas` (the filter nav), `area_link` (modifier `current`) and `entry_area`.

## 5. Screenshots

- Requires Active Storage in the host. The feature is off, with a boot-time log, when `ActiveStorage` isn't loaded or `config.images = false`.
- `Entry has_many_attached :images`, with the order stored in an `image_order` jsonb column or through attachment position. Pick the simpler option that keeps ordering.
- **From GitHub:** when a draft is written, images in the issue or PR body are fetched and attached.
  - Fetch `bodyHTML` through GraphQL. Its `<img src>` URLs on private repos are short-lived signed URLs (`private-user-images.githubusercontent.com`), so they are downloaded straight away.
  - At most `config.max_images_per_entry` images (default 4), each at most 5 MB.
  - Only `image/png`, `image/jpeg`, `image/gif` and `image/webp` are kept, verified by magic bytes, not by extension.
  - Only GitHub image hosts are fetched, from an allowlist: `private-user-images.githubusercontent.com`, `user-images.githubusercontent.com`, `github.com/user-attachments`, `camo.githubusercontent.com`. Redirects are followed only within the allowlist.
  - Timeouts are set.
  - Images are fetched once per draft, and again on forced regeneration only if the entry has no images yet. Approved entries are never silently changed.
- **Admin:** shows thumbnails, with remove, move up or down, and upload (multiple files, same type and size checks). Alt text per image defaults to the entry title.
- **Public:** images render under the body, on the changelog list (the first image only) and on the permalink (all of them), with `loading="lazy"`, width and height when known, and alt text. The feed includes them.
- Class keys: `entry_images` and `entry_image`.

## 6. Translations (auto-published)

- `config.locales = []` by default, for example `[:es]` for Trackberry.
- A new table `shiplog_entry_translations` (`entry_id`, `locale`, `title`, `body`, `source_digest`, unique on `[entry_id, locale]`).
- **Writing:** when an entry is approved, or its approved title or body changes, a `TranslateEntryJob` runs for each configured locale.
  - It uses the host's `rewriter` callable with a translation prompt: translate the given title and body into the locale, keeping the meaning, tone and product names, and return JSON `{title, body}`. The source text is inside the `<source>` delimiters.
  - It stores the result with the digest of the source text, so a stale translation is replaced.
- The translation is published straight away, with no second approval (the user's choice). Admins can see and edit it on the entry page under a Translations section; an edit is kept until the English text changes.
- **Public:** pages render the translation for `I18n.locale` when one exists and is current, and fall back to English otherwise. The roadmap does too. That covers roadmap entries, which get translated on approval like the rest.
- **Host routing:** Trackberry currently redirects `/es/roadmap` to English. Removing that redirect is the Trackberry follow-up's job. In the gem, pages are already rendered under whatever `I18n.locale` the host sets.
- I18n: add `config/locales/es.yml` for the gem's own UI strings, as a courtesy, since Trackberry is the first host using it.

## Cross-cutting

- Migrations are additive and reversible, in one `20261027000002_shiplog_0_3_0.rb`. They add `entries.slug`, `entries.area_id`, the areas table, the translations table, and an index on `entries (status, approved_at)`.
- **Backfill:** the migration gives every approved feature and change a slug (oldest first), and a rake task, `shiplog:backfill_slugs`, repeats it for entries approved by older code during a deploy window. The public pages never write: an approved entry without a slug renders without a link.
- Every new public string gets an English `default:` in `t()`.
- `render_digest` includes `locales`, `images` and `max_areas`.
- README sections and generator template keys for everything above. A CHANGELOG `## 0.3.0` with upgrade notes.

## Build order

A: permalinks, feed, unseen. B: areas. C: screenshots. D: translations. Each group is reviewed by a reviewer agent, then there is a final release review, the live GitHub test (`bodyHTML`), and Trackberry dev screenshots before the PR.
